# Domain docs

This repository uses a single domain context.

## Read before exploration

- Read `CONTEXT.md` when it exists.
- Read relevant records under `docs/adr/` when they exist.
- Proceed silently when either location is absent.

## Consumer rules

- Use glossary terms from `CONTEXT.md` in specifications, tasks, proposals, hypotheses, and tests.
- If a term is missing, reconsider it or note a real glossary gap for domain modeling.
- Report conflicts with an existing ADR instead of silently overriding the decision.
- Keep the glossary separate from Spec Kit specifications and `.specify/memory/constitution.md`.

Create `CONTEXT.md` or ADR files only when real terms or decisions need documentation.
